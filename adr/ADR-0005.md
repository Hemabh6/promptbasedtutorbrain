# ADR-0005: Close the four dangling runtime contracts before implementation

**Status:** Accepted — 2026-07-19

## Context

Phase 1 was accepted and tagged `v0.2.0` as a complete specification baseline. Phase 2
implements the first working Tutor Brain against those specifications.

Tracing the Phase 2 session flow against the Phase 1 contracts surfaced four points where a
specification references a contract that does not exist.

## Problem

One of the four is a genuine defect rather than an omission:

**`source_event_id` is a required field** in both `memory.json` and `revision.json`, and
[ADR-0002](ADR-0002.md) makes append-only events the source from which all derived views are
rebuilt. No `event.json` exists. The central contract of the persistence model is unspecified,
and every reference to it dangles.

The other three block implementation without being defects:

| Missing | Referenced by | Consequence |
| --- | --- | --- |
| Topic contract | `topic_id` is required in four schemas; `exam_weight` is required by the Decision Engine scoring formula | No referent for the system's most-used foreign key, and no source for a required scoring input |
| Rubric contract | "the total is computed by application code from configured weights" | The weights are never defined anywhere |
| Session contract | `memory.json` states working context is "session-bounded and never persisted here" | No contract can satisfy "continue tomorrow from where they stopped" |

Additionally, `urgency`, `exam_weight`, `forgetting_risk`, and `effort_cost` each appear
exactly once in the repository — inside the scoring formula itself. They are undefined terms.

## Decision

Add four schemas to `schemas/`: `event.json`, `topic.json`, `rubric.json`, and `session.json`.
Define the four scoring inputs in terms of fields these contracts now supply.

Phase 1 is treated as **amendable for defect repair**, not reopened for design. The amendment
adds no capability and changes no accepted behaviour: each new contract is the missing referent
of an existing Phase 1 requirement.

Separation of concerns is preserved:

- `event.json` holds **evidence**; `session.json` holds **working context** and no evidence.
- `topic.json` is a **static syllabus reference**, not learner state; learner state remains in
  `student.json`.
- `rubric.json` holds **weights only**; dimension scores remain in `answer.json`.

## Alternatives Considered

| Alternative | Why rejected |
| --- | --- |
| Define the contracts inside Phase 2 code only | Splits the schema source of truth across two phases and leaves the `event.json` defect unrepaired in the specification. |
| Infer events from existing records | Events would be reconstructed from their own derived views, inverting ADR-0002 and making the ledger unauditable. |
| Store session context in `memory.json` | Directly contradicts that schema's own statement that working context is never persisted there. |
| Defer until a defect is proven at runtime | The dangling `source_event_id` is provable by inspection today; deferring guarantees an implementation invents a private contract. |
| Put `exam_weight` in `student.json` | Syllabus weight is a property of the syllabus, not the learner; it would be duplicated per student. |

## Tradeoffs

**Accepted cost:** the frozen baseline is amended in its first week, which weakens the freeze
as a signal; `schemas/` grows from five contracts to nine; a topic registry must be seeded with
real syllabus data before the system is usable.

**Gained:** the persistence model is complete and auditable, the Decision Engine scoring
formula becomes computable, and session resumability — a Phase 2 Definition of Done
requirement — has a contract instead of an implementation detail.

## Consequences

- `schemas/` contains nine contracts. `schemas/README.md` and `CHANGELOG.md` are updated.
- The Decision Engine's scoring inputs are now computable:
  `exam_weight` from `topic.json`; `effort_cost` from `topic.baseline_effort_cost`;
  `forgetting_risk` from `revision.json` interval state; `urgency` from `next_due_at` and
  deadline proximity.
- `topic.aliases` allows deterministic resolution of "Teach me Fundamental Rights" to
  `polity.fundamental_rights` **without a model call**, keeping topic resolution inside the
  Tutor Brain per [ADR-0001](ADR-0001.md).
- No Phase 1 document required a behavioural change. The Constitution is untouched.
- Phase 1 specification version moves to 0.3.0.

## Future Considerations

- The topic registry will need a real syllabus import path; hand-authoring does not scale past
  a demonstration set.
- `event.payload` is intentionally open (`additionalProperties: true`) and validated by the
  owning engine. If payload shapes proliferate, per-kind sub-schemas may be justified.
- Rubric weights are currently uniform by default and will need calibration against observed
  evaluator behaviour in Phase 6.
